# comfy-draftsman v0.15.0 — Competitive-gap round

## Context

Comfy Org shipped an official local MCP server (`Comfy-Org/comfy-mcp`, 39 tools,
a stdio wrapper around `comfy-cli`). A source-level comparison against draftsman
found the two servers barely overlap: theirs owns *environment and lifecycle*
(install/launch/update ComfyUI, install node packs, download models, hardware
routing, credit-gated partner generation), draftsman owns *graph authoring*
(their entire "workflow building" surface is slot-setting on an existing
template — no add-node, no connect, no rewire, no layout).

Four gaps are worth closing. They are the ones where the official server does
something draftsman genuinely cannot, and where the fix does not require
draftsman to grow a `comfy-cli` dependency:

1. **Distribution.** They are `pip install comfy-mcp`; draftsman is `uv sync`
   from source. This is a bigger practical advantage than any single feature.
2. **Hardware honesty.** They detect GPU/VRAM and tell the user *before* a
   40-minute download whether a model will run. Draftsman reports VRAM in
   `get_instance_info` and offers no verdict.
3. **Spend safety.** Partner/API nodes cost real money. They gate every spending
   call behind MCP elicitation. Draftsman queues them with no confirmation and
   only checks whether `COMFY_API_KEY` is set.
4. **Agent onboarding.** Their handshake `instructions` block teaches canonical
   flows once at connect time. Draftsman has one, but it predates capacity and
   spend concepts.

Explicit non-goals: instance lifecycle, node-pack installation, and model
downloading. Those need `comfy-cli`, are the official server's moat, and are the
least interesting half of the problem. `resolve_missing_nodes` naming the pack
and handing it to the human stays the right behavior.

Intended outcome: draftsman is `pip`-installable, refuses to let a user sink a
render into a GPU that cannot hold the model, refuses to spend credits without
consent, and says so at the point of use — **without measurably growing what
every request pays for**, and with every change verified as far as a
Claude-Code-on-the-web session (no live ComfyUI) can verify it.

## The governing constraint: token budget

Measured on the current tree (`0.14.1`):

| Surface | Cost | Paid |
|---|---|---|
| All 29 tool descriptions + input schemas | **21,724 chars** (~5.4k tokens) | **every request** |
| `FastMCP(instructions=...)` handshake block | **885 chars** (~220 tokens) | once per session |
| Tool response payloads | varies | only when called |

The design rule for this whole round follows directly:

> **Push cost into the response path; keep it out of the always-loaded surface.**

Practically, that means:

- **Zero new tools.** 29 tools in, 29 tools out. A new tool costs its full
  description on every request, forever, whether or not anyone calls it.
- **Net-zero docstring growth.** Any added sentence must be paid for by trimming
  an existing one. (`run_workflow` alone is already 1,951 chars of description;
  commit `4d2dce6` trimmed it once for exactly this reason.)
- **Net-zero handshake growth.** Do not add capacity/reuse bullets to the
  `instructions` block.
- **The response teaches, not the description.** Every gate in this round fires
  *before* anything irreversible happens, so the explanation can live in the
  returned `hint` — read only by the agent that actually hit the gate, paid for
  only then. This is the "lazy loading" you asked for, and it applies to the
  spend gate, the capacity warning, and the fit verdict alike.
- **Silence on the happy path.** A block that says "everything is fine" is pure
  cost. Emit `fit` / `capacity` **only** when the verdict is actionable.
- **One new parameter total** across the entire round (`run_workflow`'s
  `confirm_spend`), because the fallback path requires the agent to be able to
  pass it. Everything else is inferred, not parameterized.

Phase 5d turns these into failing tests rather than good intentions.

## Phase 2 — Hardware / VRAM fit verdict

*Token cost target: **zero new parameters, zero always-on payload.** The verdict
is computed automatically and emitted only when it has something to say.*

**Files:** `src/comfy_draftsman/knowledge/__init__.py`,
`src/comfy_draftsman/knowledge/families/{sdxl,sd15,flux,wan}.yaml`,
`src/comfy_draftsman/server.py`, `docs/PERMISSIONS.md`.

### Schema

New **optional** `hardware:` block in the family YAML, valid at family level and
inside a `variants:` entry (`get_guidance` already deep-merges variant overlays
at `knowledge/__init__.py:118-126`, so variant-level hardware works for free):

```yaml
hardware:
  vram_gb: {minimum: 10, recommended: 16}
  notes: "fp8 checkpoint; fp16 needs ~24GB. Offloading trades speed for VRAM."
  source: "https://..."      # REQUIRED whenever vram_gb is present
```

Populate only `sdxl`, `sd15`, `flux`, `wan` — families with solid public
sourcing. The other five (`chroma`, `krea2`, `ltx`, `qwen_image`, `sd35`) get
**no** `hardware` block and correctly report `unknown`.

### Logic

Add to `knowledge/__init__.py` (pure, no I/O, trivially testable):

```python
def fit_verdict(guidance: dict, devices: list[dict]) -> dict | None
```

- Picks the largest-VRAM device from `/system_stats`'s `devices`.
- **Returns `None` when there is nothing worth saying** — no `hardware` block,
  no devices, or the model comfortably fits. `None` means the caller emits no
  key at all. This is the single most important token decision in the phase:
  the overwhelmingly common call returns zero extra bytes.
- Otherwise returns a small dict: `verdict` (`tight` | `insufficient`),
  `vram_total_gb`, `required_gb`, `advice`, `source`.
- **Compare `minimum`/`recommended` against `vram_total`, not `vram_free`.**
  A free-VRAM shortfall is a "release cached memory first" situation, not a
  model incompatibility — conflating the two produces a wrong verdict every
  time another job is resident.
- Separately, when `vram_free` is below `minimum` but `vram_total` is not,
  return `verdict: "tight"` with advice pointing at
  `manage_queue(action="free", unload_models=True)` — which already exists
  (`server.py:2247`).
- The `unknown` case is deliberately silent. An agent that reads "no VRAM data
  recorded, consider record_learning" on every single guidance call will learn
  to ignore it, and it costs tokens forever. The research directive already
  lives in the `research:` field each family YAML carries.

### Surfacing — all automatic, no new parameters

- **`get_model_guidance`** (`server.py:2365`): **no `check_fit` parameter.**
  When a family is given, compute the verdict and attach a `fit` key only if
  `fit_verdict` returned non-`None`. Annotation changes `_READ_LOCAL` →
  `_READ_INSTANCE` (it can now reach the network). On `ComfyConnectionError`,
  emit nothing — **never raise**; the guidance itself is still the valuable part.
- **Strip `hardware` from the returned guidance payload.** The raw block
  (`notes`, `source`, both numbers) is ~40 chars×N of prose that would otherwise
  ride along on *every* `get_model_guidance` call while being useful only when
  the verdict is bad. Fold what matters into the `fit` dict; drop the rest.
  Shape it in the existing `_cap_sources` pass at `server.py:223`.
- **Cache the device list for the process lifetime.** Add a `_devices()`
  accessor beside the existing lazy accessors (`server.py:114-142`), holding
  `/system_stats` device totals in `_State`. VRAM *total* does not change while
  ComfyUI is running, and total is what drives the verdict — so this is one HTTP
  call per session, not one per guidance lookup. Re-read live only in
  `run_workflow`'s preflight, where free VRAM matters. Keep the accessor
  **synchronous-safe** per the INVARIANT comment at `server.py:66`: populate it
  from an `await` inside the calling tool, not inside the accessor.
- **`get_instance_info`** (`server.py:453`): add normalized `vram_total_gb` /
  `vram_free_gb` alongside the existing raw byte fields. Purely additive, ~2
  keys, and it is a once-per-session orientation call.
- **`run_workflow`** (`server.py:1663`): preflight. Detect the family with the
  existing `knowledge.detect_family(...)`, compute the verdict, and attach a
  `capacity` key **only** when non-`None`. **This never blocks a run** —
  draftsman gates only on `validate()` errors, and a curated floor is not
  authoritative enough to refuse someone's own hardware. Model it on the
  existing best-effort `queue_busy` check at `server.py:1707` (wrapped in
  `contextlib.suppress`, an unreachable instance never breaks a run).
- **Docstrings:** describe this in **at most one clause** each, paid for by
  trimming existing text. The `fit`/`capacity` blocks are self-describing when
  they appear; an agent does not need to be told in advance about a key that
  shows up only when it matters.
- **`docs/PERMISSIONS.md`**: `get_model_guidance` is no longer closed-world;
  move it in the allowlist section and say why.

## Phase 3 — Partner/API spend gate

*Token cost target: **one new parameter** (`confirm_spend`), plus a
`_confirm` helper shared by three call sites. All explanatory text lives in the
gate's response, not in any docstring.*

**Files:** `src/comfy_draftsman/graph/validate.py` (or a small new
`graph/spend.py`), `src/comfy_draftsman/server.py`,
`tests/fixtures/object_info_trimmed.json`.

### Detection

ComfyUI's `/object_info` carries a per-class `api_node` boolean — confirmed
present in `tests/fixtures/object_info_trimmed.json` (four core classes carry
`"api_node": false`). Add:

```python
def api_nodes(wf, object_info) -> list[dict]   # [{node_id, class_type}]
```

- Primary signal: `object_info[cls].get("api_node") is True`.
- Secondary: `category` starting with `api node` (case-insensitive).
- **Missing field ⇒ not flagged.** Unknown is not paid. An instance too old to
  emit `api_node` must not have every node treated as billable.
- Pure dict scan, no I/O. **Call it only in `run_workflow`** — not in
  `validate`, `lint`, or `organize`, where it would cost payload for no gain.
- Add one `api_node: true` entry to the trimmed fixture so tests have something
  to bite on.

### Gate

`run_workflow` gains `confirm_spend: bool = False` and a FastMCP-injected
`ctx: Context` parameter. FastMCP hides `Context` from the tool's JSON schema,
so it costs nothing on the wire — the Phase 5d schema test verifies that claim
rather than assuming it. When the graph contains API nodes and `confirm_spend`
is false:

1. Try `await ctx.elicit(...)`. The locked SDK is **mcp 1.28.1** and
   `Context.elicit` is available (verified).
2. Accept → proceed. Decline → return
   `{"status": "spend_declined", "api_nodes": [...]}` — a normal return, not an
   exception, matching the `queue_busy` precedent at `server.py:1712`.
3. Client without elicitation capability (raises) → return
   `{"status": "spend_confirmation_required", "api_nodes": [...], "hint": "…
   re-run with confirm_spend=True ONLY after the user has agreed"}`.

The full explanation of the gate — what spends, what `confirm_spend` does and
does not authorize — lives in that `hint` string. It is read once, by the agent
that hit the gate, and costs nothing on the other 99% of runs. `run_workflow`'s
docstring gets **one clause**, and pays for it by trimming.

Also: cap `api_nodes` in the response with the existing `_cap_findings` /
`_clip` helpers (`server.py:170`, `server.py:256`) — a graph with thirty partner
nodes must not return thirty rows.

Also: when API nodes are present and `_config().comfy_api_key` is empty, fail
early with a named error. Today that surfaces as an opaque queue-time
`Unauthorized`, which is a worse failure for the same condition.

### Same helper, two more call sites

Factor one `_confirm(ctx, message, fallback_hint)` helper carrying the
three-way degrade, then reuse it for:

- **`manage_queue`** (`server.py:2203`) — `clear`, `delete`, `interrupt`.
  Gate *precisely*: only elicit when the affected prompt_ids are **not** in
  `_State.submitted`, i.e. when the action would destroy work this session did
  not queue. The attribution logic already exists at `server.py:2225`. This is
  strictly better than a blanket confirmation — it prompts exactly when the
  user's own queued jobs are at risk, stays silent otherwise, and needs **no new
  parameter** because the condition is inferred from state draftsman already
  tracks.
- **`save_workflow(overwrite=True)`** (`server.py:2252`) — stretch goal, ~10
  lines, reuses the same helper. Low value (the default already renames rather
  than clobbers), so drop it if Phase 3 is running long.

## Phase 5 — Testing, QA and validation

This is the part that must not be skimped. Everything below runs in a
Claude-Code-on-the-web session with no ComfyUI.

### 5a. The highest-value new asset: an offline MCP protocol test

`tests/test_mcp_offline.py` (new, **not** marked `integration`).

`tests/test_mcp_e2e.py` already drives the real protocol surface via
`mcp.shared.memory.create_connected_server_and_client_session` — but it is
`integration`-marked and needs a live instance, so it never runs on web. `respx`
is already a dev dependency and already used for HTTP mocking in six test
modules (`tests/test_client.py`, `test_round8_execution.py`, …).

Combine them: mount the real FastMCP server against a `respx`-mocked ComfyUI
(`/system_stats`, `/object_info` from the trimmed fixture, `/prompt`, `/queue`,
`/history`) and exercise the whole flow through the protocol layer:

- `get_instance_info` → normalized GB fields present
- `get_model_guidance(family="flux")` on a small GPU → `fit` block present
- `get_model_guidance(family="flux")` on a large GPU → **no `fit` key at all**
- `get_model_guidance(family="ltx")` → **no `fit` key** (no data, stays silent)
- `get_model_guidance` never returns a raw `hardware` block
- `create_workflow` → `edit_workflow` → `organize_workflow` → `validate_workflow`
- `run_workflow` on an API-node graph → spend gate fires
- `run_workflow` on an ordinary graph → **no `capacity`, no spend keys**
- every tool's `readOnlyHint` annotation matches its actual behavior

The negative assertions matter as much as the positive ones: they are what keep
the happy path free.

This is a permanent capability win beyond this round — from here on, web
sessions can validate draftsman end-to-end.

### 5b. Elicitation coverage

`create_connected_server_and_client_session` accepts an `elicitation_callback`.
Assert all three branches for both `run_workflow` and `manage_queue`:
**accept** → action proceeds; **decline** → structured refusal, nothing queued
or deleted; **no capability** (omit the callback) → the
`confirm_spend=True` / confirmation instruction is returned, and again nothing
happens. The no-capability path is the one that silently regresses.

### 5c. Data-integrity tests (`tests/test_hardware_fit.py`, new)

- Every family YAML carrying `hardware.vram_gb` **must** carry
  `hardware.source`. This turns "never synthesize" from a convention into a
  failing test.
- `fit_verdict` table test: total-VRAM comparison drives
  `insufficient`; free-VRAM shortfall with adequate total drives `tight`;
  comfortable fit, no hardware block, and no devices all drive **`None`**.
- Variant-level `hardware` overrides the family-level block (exercises the
  existing merge at `knowledge/__init__.py:118`).

### 5d. Token-budget guards — the enforcement mechanism

Extend `tests/test_round18_tokens.py`, which already asserts loose payload
ceilings on the responses most likely to balloon. These are the tests that make
the budget real:

- **Total tool description + input-schema payload ≤ 22,200 chars.** Baseline
  today is **21,724**; the ceiling allows ~2% for the one new parameter and
  nothing else. No such guard exists at present, and this round adds surface to
  four tools — this single assertion governs the entire plan.
- **`FastMCP(instructions=...)` ≤ 900 chars.** Baseline **885**.
- **Tool count is exactly 29.**
- **`Context` does not appear in any tool's input schema** — verifies the claim
  that the injected `ctx` parameter is free.
- Response ceilings on `get_model_guidance` (with and without a `fit` block) and
  on the `capacity` / spend-gate payloads.

Set the ceilings from measured values, keeping the file's existing convention:
loose regression guards, not golden-master assertions. Record the final measured
numbers in the changelog.

## Risks

- **`api_node` coverage is unverified against a live instance.** The fixture
  only carries `false` values. If real ComfyUI omits the field on partner nodes,
  the category fallback carries the gate, and a live integration run (5f #1) is
  the only thing that settles it. Failing *open* (unknown is not paid) is the
  deliberate choice: over-prompting on every node would train users to click
  through the one prompt that matters.
- **Elicitation support varies by client.** The no-capability degrade path is
  the common case on some clients, so it must be as usable as the prompt.
- **Silence has a failure mode too.** Emitting nothing on `unknown` means an
  agent is never nudged to research VRAM data for the five unpopulated families.
  Accepted deliberately: each family YAML already carries a `research:`
  directive, and a hint repeated on every call is one an agent learns to skip.
- **VRAM floors age.** Quantization and offloading move the real numbers
  constantly. The `source` field and `record_learning` overlay are the
  mitigation; the curated floor is explicitly a floor, not a ceiling.
- **Annotation change on `get_model_guidance`** may re-prompt users who had it
  allowlisted. Called out in `docs/PERMISSIONS.md` and the changelog.
